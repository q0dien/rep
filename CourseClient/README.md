# University Course Management System

## 1. Описание проекта

University Course Management System - это учебное веб-приложение для управления университетскими курсами, студентами, преподавателями и оценками. Проект состоит из REST API и отдельного MVC-веб-клиента, который взаимодействует с API и отображает информацию пользователю.

В рамках задания были реализованы работа с курсами, аутентификация и авторизация пользователей, распределение прав доступа по ролям, профили студентов и преподавателей, запись на курсы, выставление оценок и версионирование API.

## 2. Используемые технологии

- C#
- ASP.NET Core Web API
- ASP.NET Core MVC
- Entity Framework Core
- PostgreSQL
- ASP.NET Core Identity
- JWT Bearer Authentication
- Swagger / OpenAPI
- Git и GitHub

## 3. Структура проекта

- `CourseApi/` - серверная часть REST API.
- `CourseApi/Controllers/` - контроллеры API.
- `CourseApi/Controllers/V2/` - контроллеры второй версии API.
- `CourseApi/DTOs/` - объекты передачи данных.
- `CourseApi/Data/` - работа с контекстом базы данных.
- `CourseApi/Migrations/` - миграции Entity Framework Core.
- `CourseApi/Models/` - модели курсов, студентов, преподавателей и записей.
- `CourseApi/Screenshots/` - скриншоты работы приложения.
- `CourseClient/` - MVC-веб-клиент.

## 4. Основные возможности

### 4.1. Работа с курсами

API поддерживает получение списка курсов, просмотр отдельного курса, создание, изменение и удаление записей. Для защищённых операций учитываются права доступа пользователя.

### 4.2. Аутентификация и авторизация

Для управления пользователями используется ASP.NET Core Identity, а для передачи данных аутентификации - JWT-токены.

Реализованы регистрация и вход пользователей, получение информации о текущем пользователе, проверка токена и ограничение доступа к защищённым операциям.

### 4.3. Роли пользователей

В системе предусмотрены три роли:

- **Admin** - административные операции и управление пользователями.
- **Teacher** - работа с оценками и доступными преподавателю учебными данными.
- **Student** - просмотр доступных данных и работа со своими учебными записями.

Проверки доступа не позволяют студенту выполнять административные действия или самостоятельно назначать себе роль администратора.

### 4.4. Профили и учебные записи

Реализованы профили студентов и преподавателей, запись студентов на курсы и работа с оценками. Данные пользователей хранятся в PostgreSQL.

### 4.5. Версионирование API

В проекте предусмотрены версии API v1 и v2. Вторая версия возвращает расширенную информацию о курсах, включая сведения о преподавателе и количестве записей на курс.

### 4.6. MVC-клиент

Веб-клиент использует HTTP-запросы к REST API. Он предназначен для отображения списка курсов и страниц приложения, а адрес API задаётся через конфигурацию клиента.

## 5. Установка и запуск

Для запуска необходимы установленный .NET SDK, PostgreSQL и настроенная база данных.

### 5.1. Настройка базы данных

Создайте или настройте базу PostgreSQL в соответствии с конфигурацией серверного приложения. Параметры подключения должны соответствовать настройкам в `CourseApi`.

В проекте используются миграции Entity Framework Core для создания и обновления структуры базы данных.

### 5.2. Запуск API

Откройте первое окно PowerShell и выполните:

```powershell
cd "$HOME\Desktop\rep-upload\CourseApi"
dotnet restore
dotnet ef database update
dotnet run --urls "http://localhost:5150"
```

Команда `dotnet ef database update` применяется после настройки подключения к базе данных. Если инструмент `dotnet ef` не установлен, его необходимо установить с совместимой версией Entity Framework Core.

После запуска API Swagger доступен по адресу:

http://localhost:5150/swagger

### 5.3. Настройка JWT

JWT-ключ необходимо хранить в переменной окружения или другом локальном хранилище секретов, а не в опубликованном исходном коде.

Пример настройки в PowerShell:

```powershell
$env:Jwt__Key = "YOUR_LOCAL_SECRET_KEY"
```

Вместо `YOUR_LOCAL_SECRET_KEY` укажите собственный случайный секретный ключ достаточной длины. Не добавляйте его в Git. Значения Issuer и Audience должны соответствовать конфигурации приложения.

### 5.4. Запуск MVC-клиента

Откройте второе окно PowerShell:

```powershell
cd "$HOME\Desktop\rep-upload\CourseClient"
dotnet restore
dotnet run --urls "http://localhost:5065"
```

Веб-клиент будет доступен по адресу:

http://localhost:5065

Для корректной работы клиент должен обращаться к запущенному API по адресу, указанному в его конфигурации.

## 8. Безопасность

При разработке учитывались следующие требования:

- разграничение доступа на основе ролей;
- использование JWT Bearer Authentication;
- хранение паролей средствами ASP.NET Core Identity;
- проверка прав перед выполнением защищённых операций;
- хранение секретного JWT-ключа вне публикуемого исходного кода;
- использование конфигурационных файлов для настроек приложения.

Перед использованием в реальной организации необходимо дополнительно проверить конфигурацию секретов, права доступа, обработку ошибок и параметры развертывания.

Проведённое ручное тестирование позволило проверить основные сценарии работы системы и ограничения доступа. Скриншоты демонстрируют работу API, взаимодействие с PostgreSQL, документацию Swagger и пользовательский веб-интерфейс.
