# CourseApi — Web API для управления курсами

## Описание работы

В данной работе я разработала простой Web API на C# с использованием ASP.NET Core.

Цель работы — познакомиться с принципами создания веб-сервисов, HTTP-запросами и ответами, API endpoint'ами, JSON и Swagger.

В качестве примера я создала API для управления учебными курсами. Данные хранятся в памяти в виде списка, поэтому база данных в данной работе не используется.

## Используемые технологии

* C#
* ASP.NET Core Web API
* .NET
* Swagger / OpenAPI
* JSON
* HTTP

## Реализованные методы

| Метод  | Endpoint            | Назначение                    |
| ------ | ------------------- | ----------------------------- |
| GET    | `/api/Courses`      | Получение всех курсов         |
| GET    | `/api/Courses/{id}` | Получение курса по ID         |
| POST   | `/api/Courses`      | Добавление нового курса       |
| PUT    | `/api/Courses/{id}` | Изменение существующего курса |
| DELETE | `/api/Courses/{id}` | Удаление курса                |

## Модель курса

Каждый курс содержит следующие данные:

* `Id` — идентификатор курса;
* `Name` — название курса;
* `Teacher` — преподаватель;
* `Credits` — количество кредитов.

Пример данных:

```json
{
  "id": 1,
  "name": "Web Services",
  "teacher": "Teacher 1",
  "credits": 5
}
```

## Ход выполнения работы

Сначала я создала проект ASP.NET Core Web API.

После этого создала модель `Course`, в которой описала основные свойства учебного курса.

Затем я создала контроллер `CoursesController` и реализовала в нем основные HTTP-методы для работы с курсами:

* получение всех курсов;
* получение курса по идентификатору;
* добавление нового курса;
* изменение курса;
* удаление курса.

Для проверки работы API я использовала Swagger и отправляла HTTP-запросы к созданным endpoint'ам.

## Проверка GET-запросов

Сначала я проверила получение всех курсов.

Результат — статус **200 OK**, сервер вернул список из двух курсов.

[Открыть скриншот — GET все курсы](Screenshots/02_GET%20все%20курсы.png)

Затем я проверила получение курса по его идентификатору.

Для существующего курса с ID `1` сервер вернул **200 OK**.

[Открыть скриншот — GET курс по ID](Screenshots/03_GET%20курс%20по%20ID.png)

Также я проверила запрос с несуществующим ID `100`.

В этом случае сервер вернул **404 Not Found**.

[Открыть скриншот — GET 404](Screenshots/04_GET%20404.png)

## Проверка POST-запроса

С помощью POST-запроса я добавила новый курс:

```json
{
  "name": "Programming",
  "teacher": "Teacher 3",
  "credits": 6
}
```

Сервер создал новый курс с ID `3` и вернул статус **201 Created**.

[Открыть скриншот — POST добавление курса](Screenshots/06_POST.png)

После этого я отдельно проверила созданный курс через GET-запрос.

[Открыть скриншот — GET добавленного курса](Screenshots/07_GET%20добавленного%20курса.png)

## Проверка PUT-запроса

Далее я изменила созданный курс с ID `3`.

Новые данные:

```json
{
  "name": "Programming Advanced",
  "teacher": "Teacher 4",
  "credits": 7
}
```

Сервер вернул статус **200 OK** и обновленные данные курса.

[Открыть скриншот — PUT изменение курса](Screenshots/08_PUT.png)

## Проверка DELETE-запроса

После этого я удалила курс с ID `3`.

Сервер вернул статус **204 No Content**, что означает успешное удаление без содержимого в ответе.

[Открыть скриншот — DELETE удаление курса](Screenshots/09_DELETE.png)

Чтобы убедиться, что курс действительно удален, я снова выполнила GET-запрос для ID `3`.

Сервер вернул **404 Not Found**.

[Открыть скриншот — GET после удаления](Screenshots/10_GET%20после%20удаления.png)
